# R1：元の初期軌道から、全13段階で共通KKTに到達した

2026-11-15。基準19f2628。事前計画は`PLAN.md`（求解前に作成、未コミット）。本体srcは変更していない。

**保存済みの良い解を使わず、Rustの元の初期軌道（3.0595 h）から第1〜13段階すべてで共通尺度KKTに到達した。**
最終平滑化問題の目的値は1.882924837 h、充電は7区間。
前回（良い保存点から第5段階を開始）の1.879132289 hより約13.7秒長いだけである。

ただし、**事前に決めた原制約の復元は受理条件を満たさなかった。**
Ipoptは1.885854039 hの点を返したが、元の制約の残差が4.3e-9で、受理条件の1e-10を超えた。
別の設定での再試行はしていない。今回、原制約を満たすと確認できた解は無い。

論文の再現・著者のL-BFGSの再現ではない。診断用Newton・独自の尺度とAL規則・750秒の計算時間に依存する。

## 充電は第1段階で消え、第3〜4段階で作り直された

| 時点 | 充電区間（区間番号→領域） |
|---|---|
| 初期軌道 | 14区間（領域0×6、1×2、2×4、3×2） |
| 第1・2段階の終了点 | なし。全区間の充電時間の合計は0.67 h・0.35 hで、すべて領域外の区間に乗っている |
| 第3段階の終了点 | 2区間（17→領域1、25→領域2）。区間17は長さ30秒に対して充電214秒 |
| 第4段階の終了点 | 7区間（4,5→領域0、13,14,15,17→領域1、25→領域2）。うち6区間は長さ30秒に対して充電125秒 |
| 第13段階の最終点 | 同じ7区間。充電時間は区間の長さと一致（304, 30, 55, 36, 95, 617, 1226秒） |

- 第1段階のKKT点では充電区間が0になる。精度よく解いても起きるので、求解精度の問題ではない。
  粗い平滑化が領域外の充電を許すためで、純モードで電池を積分し直すと最低-2.37になる。
- **それでも第3〜4段階で充電は作り直された。** 「一度消えた立ち寄りは作り直せない」は一般には成り立たない。
  `../2026-11-14-conditioning`のtau1-seed2（rho固定・L-BFGS／Newton）で作り直せなかったのは、
  その条件での結果である。
- 作り直しの途中では、充電時間が区間の長さを大きく超える状態（30秒の区間で125〜214秒）を通る。
  平滑化がc<=sを保証しないことを使って充電が入り、後の段階で区間の長さが追いついている。
- 充電の選び方は前回と違う。前回は領域0・1・2で2区間ずつの計6区間、今回は領域0で2、領域1で4、領域2で1の計7区間。
  タスクの担当時点は今回`[3,8,12,19,23,28,35]`、前回`[2,8,13,17,22,27,34]`で、訪問順は同じ番号順。

- Ipoptは85反復・0.06秒で`Solved_To_Acceptable_Level`。固定分岐のKKTは
  stat 5.6e-9、feas 1.3e-8、comp 4.3e-9で、KKTの受理条件（1e-6）は満たした。
- しかし、その後の「元の制約の残差<1e-10」の検査で不受理になった。
  どの検査で落ちたかは`restoration_diagnosis.py`で求解せずに確かめた（`restoration-diagnosis.json`）。

- 計画で「失敗も保存し別分岐は試さない」と決めているので、許容値や反復上限を変えた再実行はしていない。
  1.885854 hは受理していない点であり、結果の数値として使わない。

## 何が分かり、何が残ったか

ROADMAPのR1の問い「良い保存済み解を与えなくても、最終問題のKKTと良い充電選択へ進めるか」に対して：

- **最終問題の共通KKT：進めた。** 第1段階から一つのランナーで、全13段階の共通KKTを確認しながら通過した。
- **良い充電選択：平滑化問題の値では前回とほぼ同じ水準に進めた**（1.8829 hと1.8791 h）。
  これまでの「元の初期軌道から」の結果は、13段階で約2.093 h（L-BFGS）か充電を失う（BFGS）、
  直接開始で復元後2.10047 hだったので、初期軌道そのものが障害だったわけではない。
- **原制約を満たす解：今回は得ていない。** 復元は受理条件に1桁半届かなかった。
- **物理変数での1e-6：未達**（2.4e-6）。前回と同じ。

依存と限界：

- 内側は診断用Newton（差分ヘッセ行列、密な固有値分解）。著者のL-BFGSでも、本体のL-BFGSでもない。
- R尺度、段階ごとの乗数リセットとrho=1e4、精度gate付きのrho増加は独自の補完である。
- 750秒かかっている。論文の「1分未満」とは比べられない。
- 図1相当の1例・1回の実行である。各100本の分布や成功率については何も言えない。
- 論文の読取値約1.8932 hより平滑化問題の値は約37秒短いが、電池が不足する点なので比較の対象にならない。

次に必要なのは、ROADMAPのR2（再利用できる実装と評価条件の固定）である。今回の結果から、
R2で先に決めるべき点が2つ増えた。

1. 復元の受理条件。Ipoptの許容レベル停止と1e-10の検査が噛み合っていない。求解前に条件を決め直す必要がある。
2. 第3段階以降でrhoが毎回1e8まで上がること。内側が`stuck`で終わる原因であり、Newton以外の内側解法へ
   移すときの障害になる。
