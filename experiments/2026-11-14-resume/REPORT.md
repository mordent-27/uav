# 2026-11-14 再開時の解の構造診断

## 結論

設定値の変更を止め、保存されていた解の区間位置・充電時間・電池残量を直接調べた。
少なくとも二つの異なる問題がある。

1. **実行不能な解の目的関数が良く見える。** 放電と判定された飛行区間にも
   `c > 0` が残り、電池の統一ダイナミクスがその充電を計算に入れている。
   実際の充放電モードで再計算すると、失敗例は電池残量が −0.311700 になる。
2. **制約違反が小さくても時間を十分に最適化できていない。** 位置と充放電の
   選択をほぼ変えずに、充電区間の待ち時間を削るだけで目的関数が下がる。
   `s1` は 3.453851 → 2.692116 h、今回のデフォルト解は 1.958805 → 1.857481 h。

元のソルバーは変更していない。診断用の後処理と、元の Rust 評価関数による
独立した再検証を追加した。論文の手法の再現と、追加の改善実験を区別する。

## 同じモードで電池残量を再計算した結果

`modes[k] = -1` は純放電 `c=0`、`modes[k] >= 0` は純充電 `c=s` として、
初期電池残量 1 から式(26)–(27)を順に計算した。
この判定は保存済みの各区間の残差が最小となるモードに基づく。
別の経路・モード選択なら実行可能となる可能性は否定しない。

| 入力 | 時間 [h] | 元の違反最大値 | 再計算した電池の最小値 | 飛行区間に残った充電による増分合計 |
|---|---:|---:|---:|---:|
| 保存 `fail3.json` | 1.192375 | 5.376e-3 | −0.311700 | 0.311744 |
| 保存 `s1.json` | 3.453851 | 2.252e-5 | 0.279082 | 0.000439 |
| 保存 `fig1.json` | 1.908766 | 1.696e-5 | 0.021691 | 0.000531 |
| 今回 `default-fig1.json` | 1.958805 | 2.960e-7 | 0.020511 | 0.000000492 |

増分は各区間の保存電池残量を始点にした局所量の和で、充電を挟むため
終端電池残量の差とは一般に一致しない。`fail3` の飛行区間では約19.3秒の充電が
繰り返し混在する。CC 領域では、純放電に比べた区間の電池増分は

\[
f_c(e,c)-e+\zeta c=(\kappa+\zeta)c.
\]

たとえば `c ≈ 0.00537 h` なら約 `0.0383`。区間ごとの小さく見える違反が
蓄積し、実際には飛べない経路を短い時間で飛べるように計算している。
これは**不完全な求解による原問題の制約違反**であり、実行可能な原モデルが
飛行中の充電を許しているという意味ではない。

## 時間短縮による確認

診断スクリプトでは次の操作だけを行った。

1. 保存済みのタスク訪問スタンプと区間モードを固定する。
2. タスク位置への微小なずれを補正し、充電区間の端点を領域内へ投影する。
3. 各区間を速度制限・最小時間以上に保ち、充電時間を二分探索で短縮する。
   全行程を再計算して電池残量が下限を割る短縮は採用しない。
4. `c=0` または `c=s` を厳密に設定し、電池残量を再計算する。
   原問題の制約を検証し、実行不能な候補は保存しない。

| 入力 | 短縮前 [h] | 短縮後 [h] | 短縮率 | 最大位置補正 [km] | Rust での原制約違反 |
|---|---:|---:|---:|---:|---:|
| 保存 `s1` | 3.453851 | 2.692116 | 22.05% | 3.89e-6 | 0（浮動小数点精度内） |
| 保存 `fig1` | 1.908766 | 1.899587 | 0.48% | 4.89e-6 | 0（浮動小数点精度内） |
| 今回のデフォルト | 1.958805 | 1.857481 | 5.17% | 1.30e-8 | 0（浮動小数点精度内） |

今回の3候補は全区間が、それぞれの固定した経路・モードについて
`max(s_min, 距離 / 許容速度)` に約 `1e-12 h` 以内で一致した。
したがって、この固定した経路・モードの範囲では時間の下界に達している。
全体の最適性は意味しない。`s1` は14充電区間とタスク前後の折り返しが残り、
時間の再調整だけでは 1.9 h 付近まで改善しない。経路の構造自体も要因である。
`fail3` は丸めたモードで電池残量が不足するため、時間短縮の対象として棄却した。

図は [default-fig1-fixed-modes.png](fixed-modes/default-fig1-fixed-modes.png)。
保存した候補の `converged=false` は意図的であり、KKT 収束を主張しない。
時間表示は診断処理だけの時間で、元の求解時間は JSON の `source_solve_seconds` に残す。

論文の図から読み取った参照値は 1.8932 h。今回の 1.857481 h はそれより小さいが、
入力座標の読み取り誤差、37スタンプと参照経路17スタンプの違い、追加の後処理がある。
論文の実験条件や最適性を再現・上回ったという主張には使わない。

## 求解ログから確認できることと仮説

確認済み:

- デフォルト解は第1段階で `rho=1e8` の上限に到達し、以後も引き継ぐ。
  全段階で内側反復の上限まで実行し、最終の停留性残差は約 `0.145`。
  原制約違反は小さいが KKT 収束はしていない。
- 保存 `s1` も最終の停留性残差が約 `1.63` あり、時間短縮できる方向が実際に残る。
- 保存 `fail3` の平滑化された実行可能性残差は、第1段階の約 `5.98e-4` から
  最終の約 `4.90e-3` まで悪化する。ペナルティは保存ログ上、全段階で `1e5`。
- 電池モデルと制約の勾配を含む既存テスト9件は通る。
  ただし、全ての探索点での正しさを保証するものではない。

機構の仮説:

- 大きいペナルティと、未収束な部分問題から次段階へ進む継続法の組合せが、
  制約を守りながら時間を下げる動きを難しくしている可能性がある。
  ペナルティ上限だけが原因と断定する比較実験はまだ行っていない。
- 他の候補の寄与が無視できるとき、タスクの訪問誤差 `d` の等式残差は
  `sqrt(d^2+eps^2)-eps ≈ d^2/(2eps)`、放電モードも
  `sqrt(c^2+eps^2)-eps ≈ c^2/(2eps)`。
  実行可能性に近づくと勾配が小さくなる。定理1が smooth-min の値・方向の
  近似精度を示していても、合成した制約の勾配の大きさや KKT 収束は保証しない。
  この数値的な退化が AL/L-BFGS の停滞に寄与している可能性がある。

## 再実行

全て `uav/` を作業ディレクトリとする。保存済み `out/` がない場合は、先に
`tar -xzf experiments/2026-11-14-resume/baseline-out.tar.gz` で復元する。
既存の `out/` に上書きしたくない場合は別のディレクトリで展開する。

```bash
cargo test
cargo build --release
target/release/uav solve --fig1 --verbose \
  --out experiments/2026-11-14-resume/default-fig1.json \
  > experiments/2026-11-14-resume/default-fig1.log
python3 scripts/diagnose_solution.py \
  out/s1.json out/fail3.json out/fig1.json \
  experiments/2026-11-14-resume/default-fig1.json \
  --out experiments/2026-11-14-resume/diagnosis.json \
  --segments-dir experiments/2026-11-14-resume/segments \
  --polish-dir experiments/2026-11-14-resume/fixed-modes
python3 scripts/verify_solutions.py \
  out/s1.json out/fail3.json out/fig1.json \
  experiments/2026-11-14-resume/default-fig1.json \
  experiments/2026-11-14-resume/fixed-modes/*.json \
  > experiments/2026-11-14-resume/rust-validation.log
uv run scripts/plot_solution.py \
  experiments/2026-11-14-resume/fixed-modes/default-fig1-fixed-modes.json \
  experiments/2026-11-14-resume/fixed-modes/default-fig1-fixed-modes.png
```

本環境では matplotlib を含む既存の Python 環境を使って図を生成した。
診断の時間は実行ごとに変動する。
