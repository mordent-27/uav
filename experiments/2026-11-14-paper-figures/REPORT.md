# 論文の図1〜3の描画データの読み取り

2026-11-14。論文の図はベクタ図なので、本文に書かれていない設定と、著者自身の
結果の分布を描画データから読み取った。求解器は使っていない。
読み取りは作業の初期に行って `src/instance.rs` と `data/paper_fig3.csv` に使っていたが、
手順が保存されていなかったので、スクリプトにして再実行し、同じ値になることを確認した。

## 再実行

`uav/` で実行する。Python 標準ライブラリと poppler の `pdftocairo` が必要。

```bash
python3 scripts/extract_paper_figures.py ../2609.40201v1.pdf --out-dir data
```

出力は `data/paper_fig1_fig2.json` と `data/paper_fig3.csv`。標準出力は `run.log` に保存した。
再生成した `paper_fig3.csv` は以前のファイルとバイト単位で一致した。

  (-5, -7)半径1.5 [km]。始点は領域1の中心、終点は領域4の中心。タスクは7個。
  いずれも本文に数値がなく、`src/instance.rs` の値はここから来ている。
- **論文の解（図1・図2a）**：頂点17個、充電4回、総時間1.8932 h、終了時の電池0.002。
  頂点と時刻を組み合わせると、飛行区間の速さは35.51〜35.99 km/h（上限36）、

## 読み方の限界

- 位置の精度は描画の丸め程度（約1e-3 km）。終点のy座標は-7.001と読めるが-7とした。
- 軸の目盛りの数値との対応は図の表示から人が読み、スクリプトの定数に固定している。
  目盛り線の本数と縦横の縮尺の一致はスクリプト内で検査している。
- 図2aの曲線は描画時に一部の点が間引かれている。間隔は最小間隔の整数倍として数えた。
  N=17は推定で、著者が同一直線上の時点を描画前に除いた可能性は排除できない。
- 図3の点は横方向にばらつきが付けてあり、同じ問題例の3手法を対応づけられない。
  比は分布どうしの比較である。時間切れは599分以上の点を数えた。
- SCIP・Juniperの目的関数は10時間以内の最良の実行可能解で、大域最適値とは限らない。
- 違反の値は論文の定義どおり単位が混在している。1e-3という閾値はこちらで置いた
  目安で、論文は成功の閾値を定めていない。
