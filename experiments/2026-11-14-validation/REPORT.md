# 重要度に沿った第1・第2検証

2026-11-14。事前の条件は `plan-before.tar.gz` と `plan-stage2-before.tar.gz`。
原文書はワークスペースの `human/validation_plan.md`。最新の関係文書を
`human-notes.tar.gz` に保存する。実験の意味を後から変更しないため、判定閾値・例・
比較内容を実行前に別コミットで記録した。

## 検証順

1. 解の実行可能性と、単一車両のサービスの整合性（完了）。
2. 冗長な必要条件c<=sを残す効果（完了）。
3. 単位・残差の尺度（未着手）。
4. ALのペナルティと段階進行、最良実行可能解の保持（未着手）。
5. Nと初期軌道の構造（未着手）。
6. 零点集合を保つpsi・近似不等式・修復（未着手）。
7. 安定化LSEとの同程度の誤差での比較（未着手）。

数式や既知の反例で確定した命題は再実験せず、通常の出力での影響と対策の効果を調べる。
運用要件がまだ決まっていない加速度や観測時間等は今回の比較へ混ぜない。

## 条件

図1相当1件と、tau=1,3,5,7 × seed=0,1,2の直接指定12件。全13件。
全て現行デフォルト、half=9, reach=6。1件90秒、同時実行最大2件。
全件完了し、除外・再試行はない。実行コマンド・ソースのハッシュ等は
`provenance.json`、各ケースの`run.json`、比較用のprovenanceに記録。

原制約の許容値は距離1m、モード時間と区間時間上下限1秒、電池・ダイナミクス1e-6。
初期・終端位置等は別に1e-9で確認する。原論文の閾値という意味ではない。
モード候補は成分をこれらの許容値で割った最大値が最小のものを採用。
今回の13件では保存されたモード判定との不一致はなかった。

「単一車両まで合格」は、原制約に加え、純充放電での全行程の電池上下限と、
各領域を同じ一台の車両が担当する場合の再訪間移動も満たすこと。
それ以外の運動力学や未指定の車両初期位置まで保証する意味ではない。

### 原制約の修復だけでは直らない例

既存の固定経路・モードの時間短縮は6件で候補を生成し、全6件ともRustで
原制約違反0、密な電池時系列の上下限も確認した。そのうち4件は車両の再訪に失敗した。

例えばtau3-seed1の修復後は0.829173h、原制約違反0だが、同じ領域の次の充電に
向かう間隔が308.002秒、必要距離が1.564148kmある。車両が移動できる距離は
約0.924007kmなので0.640142km不足する。約213.381秒の追加移動時間が必要。
これはALの誤差や平滑化の残差だけを小さくしても消えない。

ただし、複数の待機車両等によりサービスを保証する運用は対象外。
固定モードへの丸めの失敗は、あらゆるモードの組合せが不可能という証明ではない。

## 第2検証：c<=sの追加だけで何が変わるか

本体のsrcを変更せず、`cap-comparison/cap-model.rs` に追加モデルを生成した。
差分は同ディレクトリの`cap-model.diff`。変更する制約は

\[
v_d(c_k-s_k)\le0
\]

のみであり、既存の時間上下限と同じ尺度でALへ加えた。
両条件とも同じコンパイルオプションで生成し、各段階末の充電時間逸脱を計測した。
入力と初期解の一致を確認した。計測を加えたベースラインの13件の目的関数は
第1検証と1e-12h以内で一致した。

| 判定 | 追加なし | c<=s追加 |
|---|---:|---:|
| 中間または最終段階でc-sが1秒超 | 13/13 | 0/13 |
| 最終解でc-sが1秒超 | 1/13 | 0/13 |
| 原制約が許容値内 | 7/13 | 7/13 |
| 純モードでの電池上下限が許容値内 | 6/13 | 5/13 |
| 単一車両まで合格 | 2/13 | 2/13 |
| KKT収束 | 0/13 | 0/13 |

追加なしの段階末最大逸脱は約331秒、追加ありは約0.179秒。
これは段階末の値であり、内側の線探索中の全試行点の値は評価していない。
追加制約もALで扱うため、未収束時の厳密なc<=sの保証ではない。
両方の「2件」は同じ組合せではなく、図1が電池再計算で落ち、tau3-seed2が合格に変わった。

結論は、**必要条件の追加は定義域逸脱を抑えたが、この13件では最終の合格件数を
増やす効果やKKT収束の改善は確認できなかった**。係数の追加探索はしない。
実行不能な解の目的関数が下がっても、それを改善として集計しない。

### 補足の観察：初期解の保持

追加の監査で、初期解は12/13件が原制約の許容値内だった。
ベースラインの最終解が不合格の6件は、全て初期解では合格していた。
現行実装は最終段階の点を返し、実行可能な初期解・途中解を保つ処理を持たない。
今後の安全な出力処理として、最良実行可能解の保持を検討する。
この観察は事前に定めた改善比較の結果ではなく、監査後の追加所見。
初期解の単一車両条件までの合格は5件で、初期解へ戻すだけでも問題は残る。

## 再実行

`uav/` が作業ディレクトリ。

```bash
cargo build --release
python3 experiments/2026-11-14-validation/run.py
python3 scripts/verify_solutions.py \
  experiments/2026-11-14-validation/cases/*/raw.json \
  experiments/2026-11-14-validation/cases/*/polished.json
python3 experiments/2026-11-14-validation/compare_cap.py
python3 scripts/verify_solutions.py \
  experiments/2026-11-14-validation/cap-comparison/baseline/*/raw.json \
  experiments/2026-11-14-validation/cap-comparison/capped/*/raw.json
```

`run.py`は完了記録のあるケースを再計算せず再集計する。`compare_cap.py`は比較を
再実行して出力を更新する。最初の結果を残す場合は別チェックアウトで実行する。
計算時間・コンパイル結果は環境に依存する。

## 限界と次の未検証項目

少数の固定例による探索的な比較であり、母集団の成功率や論文の失敗率ではない。
単一車両は明示した追加の運用条件。今回決めた許容値も論文の成功基準ではない。
次は順位3の尺度・単位の対応を確認し、その後に順位4のALの進行規則へ進む。
重要度の低い近似関数の入替えを先に実験しない。
